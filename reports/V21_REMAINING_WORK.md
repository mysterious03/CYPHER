## 2. Ranked Top 5 Technical Improvements

Ranked by real-world perception impact, scientific validity, and implementation feasibility:

### Priority 1: Retrain Waterlogging Segmenter with Authentic Pixel Annotations
- **Problem:** `runs/water_segmenter/best_water_model.pt` was trained on synthetic pseudo-masks generated by color and brightness thresholding. As a result, it misclassifies specular glare on dry asphalt as standing water puddles.
- **Solution:** 
  1. Ingest an authentic pixel-annotated puddle dataset (such as RPI Puddle Dataset or Cityscapes wet subset).
  2. Retrain the existing LRASPP MobileNetV3 architecture using a combined Cross-Entropy + Dice Loss.
  3. Validate against real rainy dashcam video to ensure zero false positives on dry reflective road patches.
- **Estimated Effort:** 1–2 GPU days; High ROI.

### Priority 2: Resolve D10 Transverse Crack Recall Collapse via B1 Candidate Selection
- **Problem:** D10 transverse cracks have only 68 training instances compared to 2,021 D20 alligator cracks (30x imbalance). The B0 detector predicts D10 with $<0.017$ maximum confidence, achieving 0 true positives on the holdout set.
- **Solution:**
  1. Conclude the B1 evaluation gate comparing B1A (D10 resampling), B1B (effective-number loss re-weighting), and B1C (perspective augmentation).
  2. Select the winning checkpoint that recovers D10 recall $>40\%$ without causing a precision collapse or false positive spike on clean road textures.
  3. Standardize the selected model as the new `M1_ROAD_DAMAGE` production checkpoint.
- **Estimated Effort:** 1 day (evaluation script already created in `scripts/evaluate_b0_b1_gate.py`).

### Priority 3: Metric Camera Calibration Engine for Pothole Depth & IRI Estimation
- **Problem:** `PotholeGeometryAdapter`, `FrictionAdapter`, and `RoughnessAdapter` are currently held back by `CALIBRATION_REQUIRED` and `SENSOR_REQUIRED` status gates because RGB pixels cannot be mapped to physical centimeters or friction coefficients.
- **Solution:**
  1. Implement an Inverse Perspective Mapping (IPM) module parameterized by camera mount height $h$, pitch angle $\theta$, and focal length $f_x, f_y$.
  2. Implement an automated vanishing-point estimator to calculate camera pitch dynamically from road boundaries.
  3. Convert detected pothole bounding polygon pixels into metric dimensions ($cm^2$ area and relative estimated volume).
- **Estimated Effort:** 2–3 days of geometric computer vision implementation.

### Priority 4: Replace Photometric Weather Heuristic with Fine-Tuned ACDC Classifier
- **Problem:** `WeatherAdapter` relies on Laplacian variance and RMS contrast thresholds. In tropical or desert environments with extreme sunlight or dust, heuristic rules misidentify clear conditions as haze or fog.
- **Solution:**
  1. Fine-tune a lightweight MobileNetV3-Small backbone on the ACDC (Adverse Conditions Dataset) covering Fog, Night, Rain, and Snow.
  2. Combine the neural weather class logit with the existing photometric illuminance measurement for environmental verification.
  3. Export model as `runs/weather_classifier/best_weather_model.pt` (approx. 5.8 MB).
- **Estimated Effort:** 1 GPU day.

### Priority 5: True Open-Vocabulary Obstacle Perception via Lightweight Zero-Shot Detector
- **Problem:** The current obstacle perception mode simply re-filters pretrained COCO classes for fire hydrants and suitcases, leaving genuine road road hazards (fallen logs, rockfalls, lost tyres, spilled construction cargo) unaddressed.
- **Solution:**
  1. Integrate an open-vocabulary zero-shot detector (such as NanoOWL or MobileCLIP + YOLO feature pyramid) optimized for ONNX / TensorRT.
  2. Provide a customizable text prompt list (`"fallen tree"`, `"large rock"`, `"spilled debris"`, `"tyre on road"`).
  3. Gate candidate bounding boxes with the `road_mask` to prevent false detections outside the drivable roadway.
- **Estimated Effort:** 3–4 days; Transforms obstacle perception into an unconstrained hazard detector.
